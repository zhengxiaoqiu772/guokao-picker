# 国考选岗器

把 2027 年国考职位表（全国 **19,426** 个职位）变成「我到底能报哪些」。

填一遍自己的报考条件，页面实时把职位表缩到你能报的那一批，并且**逐个职位给出匹配依据**——
命中的专业原文会高亮出来，让你自己复核，而不是丢给你一个不透明的「可报 / 不可报」。

全程离线。**双击 `index.html` 就能用**，不需要装任何东西，也不联网。

---

## 怎么用

1. 双击 `index.html`（Chrome / Edge 都行）。
2. 先在左侧「所学专业」里填**专业名称**，有专业代码就一起填上——这是筛得准不准的关键。
   填完代码后，下面会自动提示你可能属于哪个专业类目，点一下就加上了。
3. 在「学历 · 学位 · 届别」里选**毕业年份**。这一项很重要，见下面「应届身份」。
4. 其余条件按实际情况改，改完即时生效，没有「查询」按钮。
5. 结果分三档排下来，越靠前越确定。想进一步看，用上面的搜索框、排序和档位筛选。

条件会自动存在本机浏览器里，下次打开还在。「清空条件」一键还原。

### 应届身份

国考里的「应届」是两层意思，职位表也分两种写法，**不能当一回事**：

| 职位表的写法 | 行数 | 谁可以报 |
|---|---|---|
| 「限2027届高校毕业生」（也有只写「2027届高校毕业生」独句成行的） | 7,708 | **只限当年毕业**的那一届。择业期内的往届生不行 |
| 「限应届高校毕业生」 | 5,444 | 按报名指南**含择业期**：2025、2026、2027 届未落实工作单位的都算 |
| 完全没提 | 6,274 | 往届也能报 |

所以毕业年份要如实选：

- **2027 届（当年应届）** —— 两种岗位都能报
- **2026 / 2025 届（择业期内）** —— 能报「限应届高校毕业生」的，不能报「限2027届」的
- **非应届** —— 只能报完全不提应届的

选错一档，结果会差出上千个岗位：同样条件下 2027 届能报 2,681 个，2026 届 1,323 个，非应届 540 个。

「限应届高校毕业生」这一行不要求带「限」字。税务系统的标准句式是把性别和应届并列、谁也不带动词：

```
应届高校毕业生,男性,在本单位最低服务年限为5年
```

全表 **1,473 行**这么写。早先按「限应届」去找，这批全部漏标，非应届选下去照样能看到
（同样的画像下会多出 165 个报不了的岗位）。现在认到 5,444 行（原 3,939）。

但同样几个字，换个位置意思就反了，所以判定卡在**独立成句**上，下面四种都正确地不算限制：

```
4.如考生为应届高校毕业生,请在备注栏中注明本人具有应届高校毕业生身份,
  如考生为非应届高校毕业生,要求具有2年以上金融业机构从业经历   ← 两种身份都能报
非应届高校毕业生报考,需2年工作经历                              ← 说的是往届
招考对象可为应届高校毕业生                                      ← 「可为」是放宽
```

第一类有 1,312 行，其中 1,300 行另有真限制（照样会被认出来），真正只靠这句话的 12 行
全部落在这类两身份并列的条件句里。

这两条规则都排在左侧「备注中的要求 — 规则」里，可以各自关掉变成只提示。关掉之后，那些本来被排除的岗位会重新出现，但卡片上对应标签会标一个 ⚠，提醒你其实不符合。

### 结果怎么读

每张职位卡右上角有一枚印章，戳面就是匹配档位：

| 印章 | 档位 | 含义 |
|---|---|---|
| **精准** | 精准命中 | 你的专业名称，或 6 位专业代码，直接出现在该职位的专业栏里 |
| **类合** | 专业类命中 | 该职位招的是你勾选的专业类目（如「计算机类」），不点具体专业名 |
| **门类**（虚线框） | 门类命中 · 专业不限 | 职位写的是「专业不限」或只到门类一级，**建议人工确认** |

卡片上的「专业栏原文」是职位表里的原文，命中的部分会标红——档位是判断，原文才是依据。

标题下面竖排写着**部门代码**和**职位代码**，各带一个「复制」——报名表上本来就是分两栏填的。
两个都摆出来是因为职位代码**不唯一**：19,426 行里只有 7,178 个不同职位代码，
同一个代码会被不同部门复用，光看它认不出是哪一行。两个代码也都能直接贴进搜索框。

### 按名字找岗位（不填专业也能用）

专业栏空着时，可报职位一定是 0（全表只有 7 行不限专业）。但「想找某个岗位」跟
「我能不能报」是两件事：只要有搜索词，工具就切成**纯文字检索**——扫全部 19,426 行，
不套用左侧任何报考条件。卡片右上角的印章也从朱砂换成靛青的「检索」，
提醒你这**不是**一个「你能报」的判断。填上专业后，搜索立刻退回「在匹配结果里再过滤」。

检索范围是部门名称、用人司局、招考职位、部门代码、职位代码、工作地点、专业栏和备注。
搜代码时按位数区分：

- **六位数字**（部门代码的位数）按完整代码找。不这么做的话，搜 `102000`（外交部）
  会连带捞出职位代码 `300110200001` 里含着这六个数字的 39 个别的部门
- **十二位职位代码**整段搜，会命中所有复用该代码的部门（实测 `300110001003` 有 82 行）
- **更短的数字**仍按子串找，方便只记得职位代码前几位的情形

### 其他功能

- **备注风险提示**：备注里写明的「仅限应届」「限男性」「要求六级」「最低服务期 5 年」等会自动标出来。

  性别这一条认的是备注里**「男性」「女性」这两个词**，不要求前面带「限」字。税务系统的标准写法是
  `2027届高校毕业生,男性,在本单位最低服务年限为5年`——性别单独成句、省略谓语，全表 **3,206 行**
  这么写。早先按「限男性」去找，只认到 1,084 行，剩下那 3,000 多行选了「女」照样推上来。
  现在认到 **4,290 男 / 3,563 女**，反过来放宽到「男性」之所以不出错，是因为全表没有一行写
  「不限男性」「不适合男性」，也没有「适合男性」这类软措辞；而「配偶或子女」「妇女」
  「男子1000米(男)体能项目」这些噪声都不含「性」字，自然落选。

  侧栏把这些拆成了两处，因为它们是两回事：

  **（一）「本人情况」里的事实**——政治面貌 / 性别 / 英语等级 / 基层年限。性别和英语等级是从
  备注文本里读出来的，但「我是男是女」「我过了几级英语」跟学历、政治面貌一样，是你自己的情况，
  所以摆在这一栏。这三栏的默认值有意留成"不表态"，**不替你做你没做过的声明**：

  - 性别默认「不限」——你没选男/女之前，性别规则什么都不做
  - 英语默认「不填 / 不限」——不会因为你没填就把要求英语的职位删掉，而是把它们列出来并标 ⚠，
    同时在顶部告诉你一共有多少个（实测 281 个，其中 75 个要求六级）

  英语这一栏有四个取值，差别是实打实的：不填 ≈ 已过六级（都不排除，实测 2,681 个），
  已过四级 2,606 个，未通过四级 2,400 个。「未通过四级」是你主动做的声明，才会真的排除。
  注意「要求四级」这个标签认的是「大学英语四级 / 英语四级 / CET-4 / 专业四级」这类写法，
  表里有 18 行其实是小语种（俄语、朝鲜语、阿拉伯语）的专业四级，被一并算了进来——
  数量很小，且这几行本来就限小语种专业，副作用可以忽略。

  等级还有一整批写成**阿拉伯数字**的。外交部、中联部那批驻外岗位的标准句式是：

  ```
  大学英语4级成绩425分及以上(网上报名时,请在备注栏注明英语水平等级及分数)
  ```

  这类备注里汉字「四级 / 六级」一个都没有，共 **22 行**（4 级 2 行、6 级 20 行），
  早先整批没打上标签，选「未通过四级」照样推上来（用户报的 200110002002 就是）。
  现在认到 2,895 / 1,998（原 2,893 / 1,978）。

  只认「大学英语」这个前缀，**没有**放宽成裸的「英语4级」——民航系统有一批写的是
  「具备国际民航组织英语4级及以上能力」，那是飞行人员的 ICAO 英语等级，跟四级考试
  毫无关系（4 行，全是飞行员 / 管制员岗）。放宽到裸的「英语4级」正好会把这 4 行误判。

  **（二）「备注中的要求」里的三条开关**——应届身份 / 性别 / 英语。这三条默认**参与排除**，
  但它们都是从备注文本推断的，不是官方字段（原文语义和正则判断之间有空隙），所以各配一个开关；
  取消勾选就只提示、不排除，那时卡片上会把"你其实不符合"的那条标签标上 ⚠。

- **附加条件**：同一栏里另有四个勾选框——户籍/生源、最低服务期、体能/体检、西部/艰苦边远。
  这些是**岗位自带的负担或限制，跟你的资格无关**，所以只有勾选才排除，不勾就完全不影响结果。
  它们和「本人情况」里那两栏是互斥的：性别、英语已经各有一行输入控件，
  再在这里铺一遍同样的词，会生出矛盾状态——英语选「已过六级」又勾上「要求六级」，
  会把 75 个明明够得着的岗位扣掉。
- **收藏与对比**：点卡片上的「收藏」，底部抽屉里可以把 2–4 个职位拉成并排对比表，有差异的行会高亮。
- **结果分布**：按省份 / 机构层级 / 考试类别 / 招考人数统计当前结果，随筛选实时联动。
- **导出与打印**：「导出 CSV」给的是 21 列的完整数据（含备注原文、咨询电话、部门网站），Excel 直接打开不乱码；
  「打印 / 存 PDF」给一份去掉交互外壳的干净职位清单（数据量大时请先收窄条件再打印）。

## 匹配规则

### 硬性条件（无解释空间，直接排除）

学历、学位、政治面貌、基层工作最低年限、服务基层项目经历、意向省份、机构层级、考试类别、
职位属性、招录类别、招考人数、面试比例。

其中两处容易踩坑的：

- **学历分段生效**。职位表里 2,033 行写成「本科：XXX；研究生：YYY」的形式。
  你是本科学历时，只出现在「研究生：」后面的专业**不算命中**，反之亦然。不切段就会误报一大批。
- **服务基层项目**按「职位要求 ⊆ 你拥有的」判定，职位写「无限制」则人人可报。

### 专业匹配（三档）

专业栏是自由文本，写法极其杂乱，实际见到的形态包括：

```
财政学类、金融学类                                  ← 只写类名
080901计算机科学与技术，080910T数据科学与大数据技术    ← 代码和名称混排
本科：082803风景园林；研究生：0862风景园林             ← 本科/研究生分列
法学类（不含监狱学）                                 ← 带排除项
本科生招收计算机类(0809)；研究生招收…                 ← 中间夹着叙述文字
```

处理办法：

- **归一化**后按标点切段，逐段提取 6 位代码 / 4 位代码 / 2 位门类码 / 专业名称 / `X类` 类名。
  剥前缀虚词时只在「应」紧跟「为」时才当它是赘语（表里有「专业应为计算机科学与技术,…」这种写法）。
  先前把「应」整个列为虚词，导致**所有以「应」开头的专业名被削掉首字**——应用统计→用统计、
  应急管理→急管理，这些专业的人按名字搜是 0 个岗位。
- **排除项**（`不含`/`除外`）单独收集，命中即把该职位剔除或降档。
- **`除 X 外…` 这类反义结构不做猜测**，直接标为需要人工确认。
- **类目词表从这份表本身提取**，不套用教育部专业目录——表里有「财会审计类」「经济金融类」这类
  招录机关自编类目，硬套外部目录必然漏岗。
- **本科阶段的简写当作同一个专业**。表里有些行把「会计学」写成「会计」、「审计学」写成「审计」：

  ```
  会计,财务管理,审计
  ```

  本科专业目录里没有叫「会计」的，只有会计学（120203K），这是表的简写。不认这一层，
  同一个人填「会计」和填「会计学」会看到两拨几乎不相干的结果——实测两边只有 3 个重合，
  而填「会计学」本该能看到 565 个。现在两者结果完全一致（565 / 565，「审计」也是 510 / 510）。
  这条只在**本科阶段**生效：研究生那边「会计（1253）」「审计（0257）」是专业学位的正式名字，
  不是简写。命中后卡片上会写明「该行写作「会计」，与你填的「会计学」在本科阶段视为同一专业」。

### 为什么职位数会对不上别的软件

同一个职位代码在职位表里**不唯一**（19,426 行只有 7,178 个不同职位代码，同一代码被不同部门复用）。
本工具的身份键是「部门代码 + 职位代码」，所以按职位代码去重会得到不同的数字。

## 文件说明

```
国考选岗器/
├── index.html            页面骨架
├── styles.css            样式（公文 / 印章公报方向）
├── match.js              匹配引擎：纯函数，无 DOM 依赖，浏览器与 Node 共用
├── app.js                界面状态、渲染、收藏对比、统计、导出
├── data/positions.js     构建产物：window.GK_DATA = {…}（4.6 MB）
├── build_data.py         读 .xls → 生成 data/positions.js
├── oracle.py             独立 Python 参考实现，只用来产出对照数字
├── test_match.js         Node 测试：差分测试 + 边界用例
└── 2027年国考职位表（全国）.xls
```

**为什么数据是 JS 而不是 JSON**：页面要能从 `file://` 直接双击打开，而 `fetch()` 在 `file://`
下会被 CORS 拦住。用 `<script src>` 定义一个全局量可以绕开，代价是不用起服务器。

## 重建数据

换了新的职位表之后：

```bash
pip install xlrd
python -I build_data.py "2027年国考职位表（全国）.xls"
```

脚本会断言总行数，并打印类目词表规模、招录类别分布供核对。当前规模：
类目词表 182 条、专业代码表 334 条、类目归属映射 56 条。

## 测试

```bash
node test_match.js                 # 140 项：差分测试 + 边界用例，全绿才算过
python -I oracle.py "2027年国考职位表（全国）.xls"   # 打印参考数字
```

`oracle.py` 是**独立写的第二套实现**，和 `match.js` 各写一遍。两边的档位计数必须完全一致——
`test_match.js` 里的期望值就是从 `oracle.py` 的输出抄过去的。一套实现写错不容易发现，
两套独立实现同时错成一样就很难了。改了匹配逻辑，两边都要改，然后重跑。

## 已知边界

- **匹配结果仅供参考，以招录机关的最终解释为准。**「专业类目」的归属在不同机关手里口径并不统一，
  本工具按职位表原文和《专业参考目录》的常见对应关系判断，不可能覆盖所有情形。
  这也是每张卡都展示专业原文和高亮的原因——**结论请自己复核**。
- 备注风险标签（应届 / 性别 / 英语 / 户籍 / 服务期 / 体能）是从备注文本正则推断的，**不是官方字段**，
  可能有漏标误标。备注原文始终可见。
  其中「应届身份 / 性别 / 英语」三条**默认参与排除**（可在「备注中的要求」里分别关掉，
  关掉后只提示、并在卡片上标 ⚠）；户籍、服务期、体能、西部这四条要**手动勾选**才排除，
  不勾就只是卡片上的标签。应届那两条规则里的「只限当年毕业」这类判断，
  本质是在读中文语义，是全文里最可能出错的部分。
- 招录机关自编类目与教育部专业目录不一致的情况、`除 X 外…` 这类反义结构，不做臆测，标注人工确认。
- 数据只包含这份职位表里的信息。报名人数、竞争比、进面分数线这类数据原表里没有，因此也没有。
- 条件存在浏览器 localStorage 里，换浏览器或换电脑不会同步。
